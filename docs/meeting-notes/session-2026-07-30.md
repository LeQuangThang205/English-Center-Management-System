### API Auth

| Method | Endpoint | Request | Response |
|--------|----------|---------|----------|
| POST | `/api/auth/login` | `{email, password}` | 200 `{success, data: {token, user}, message, timestamp}` |

- Validation: `@NotBlank`, `@Email`, `@Size(min=8, max=72)` cho password (giới hạn BCrypt 72 bytes), `@Size(max=255)` khớp cột DB. Kích hoạt bởi `@Valid @RequestBody`.
- Login fail → 401 (handler `AuthenticationException` riêng, tránh bị `Exception.class` nuốt thành 500).

### Bug / kiến thức quan trọng trong phiên

1. **Spring Boot 3 / Security 6 KHÔNG tự đăng ký bean `AuthenticationManager`** — phải khai báo:
   `@Bean AuthenticationManager authenticationManager(AuthenticationConfiguration config)`.
   Nếu không, context load fail với `NoSuchBeanDefinitionException` cho `authController` (nguyên nhân khiến `contextLoads` từng đứng ở `compileJava` mà chưa chạy được `test`).
2. **`BadCredentialsException` ném từ trong controller bị `@ExceptionHandler(Exception.class)` bắt** → trả 500. Cần handler `AuthenticationException` riêng để trả 401 đúng chuẩn.
3. **Validation không tự chạy** — phải có `@Valid @RequestBody`; DTO chỉ đánh dấu annotation là chưa đủ.
4. **Test integration tránh đụng MySQL dev** — `@TestPropertySource` override datasource sang H2 in-memory (`MODE=MySQL`, `ddl-auto=create-drop`).

## Validation Error Handling & Role Authorization — Step 7.3

### Mục tiêu
Trả HTTP 400 cho lỗi validation (thay vì 500) và phân quyền theo role cho endpoint admin.

### File đã tạo / sửa

| File | Loại | Vai trò |
|------|------|---------|
| `exception/GlobalExceptionHandler.java` | Sửa | Thêm `@ExceptionHandler(MethodArgumentNotValidException.class)` → 400, message = `FieldError.getDefaultMessage()` đầu tiên |
| `config/SecurityConfig.java` | Sửa | `/api/auth/**` permitAll, `/api/admin/**` hasRole("ADMIN"), còn lại authenticated |
| `controller/AdminController.java` | Mới | `GET /api/admin/test` → `"Admin API is working"` (chỉ để test phân quyền) |
| `controller/AuthControllerTest.java` | Sửa | Thêm test validation fail → 400 + `"Email is required"` |
| `controller/AdminControllerTest.java` | Mới | STUDENT → 403, ADMIN → 200 (token sinh bằng `JwtTokenProvider`) |

### Kiến thức đã học trong phiên

1. **`MethodArgumentNotValidException`** — ném tự động khi `@Valid @RequestBody` vi phạm ràng buộc; chứa `BindingResult`/`FieldError` với message đã khai báo.
2. **400 vs 500** — lỗi validation do client gửi sai → 400 "bad request" (client sửa request); 500 là lỗi server, sai ngữ nghĩa nếu dùng cho validation.
3. **`hasRole("ADMIN")` vs `hasAuthority("ADMIN")`** — `hasRole` tự thêm tiền tố `ROLE_` (kiểm tra `ROLE_ADMIN`); `hasAuthority` kiểm tra đúng tên không tiền tố. Code gán authority `ROLE_...` nên dùng `hasRole`.

### Ghi chú thiết kế

- Thứ tự rule trong `authorizeHttpRequests` quan trọng: match đầu tiên thắng (`/api/auth/**` → `/api/admin/**` → `anyRequest`).
- 403 cho non-admin xảy ra ở tầng filter (`AccessDeniedException`), không qua `GlobalExceptionHandler`.
- `AdminControllerTest` dùng cùng cấu hình H2 như `AuthControllerTest` → Spring cache chung context.
